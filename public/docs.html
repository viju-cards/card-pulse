Architektur

Extension Kommunikation

Problem

MV3 Service Worker schläft ein und schließt den Message-Channel bevor sendResponse aufgerufen wird → Uncaught Error in content.js.

Lösung – Storage Polling Pattern
content.js
sendMessage → background.js
fetch(API) → storage.set
cp_result → content.js
poll 100ms → buildOverlay
(cp_result)
// content.js – Storage Polling (MV3-safe) var poll = setInterval(function() { chrome.storage.local.get(['cp_result'], function(r) { if (r.cp_result !== undefined) { clearInterval(poll); buildOverlay(r.cp_result); } }); }, 100); // alle 100ms, max 10 Sekunden

Stabile Extension ID

Der key-Feld in manifest.json enthält den Public Key aus extension_PRIVATE_KEY_KEEP_SAFE.pem. Damit bleibt die Extension-ID in Chrome und Edge identisch.

Extension ID: jofegljhkmoppkaiecbidoapponkjbld

⚠️ Für Chrome Web Store ZIP: key-Feld entfernen (Google vergibt eigene ID nach Genehmigung).

Set-Mapping

content.js enthält 223 Mappings von Cardmarket-Anzeigekürzeln auf TCGPlayer-Slugs (wie sie in der DB stehen).

// Cardmarket H1 Code → DB cardmarket_slug "MEW" → "sv-scarlet-and-violet-151" "SSH" → "swsh01-sword-and-shield-base-set" "SUM" → "sm-base-set" "B2" → "base-set-2"

Kartennummer-Padding: Rein numerische Nummern werden auf 3 Stellen aufgefüllt (3 → 003). Sonderformate wie Z-28, SL9, TWO werden unverändert weitergegeben.
